# VM 与跨关缓存 | 2026-10-01

这组对照验证原脚本执行的数值表示、指令存储和跨关缓存对内存与运行成本的影响。编译使用 O3、LTO、Wasm 异常处理与原输入，第一二关的 29,577 tick 及六关前缀的 15,099 tick 参与等价检查。

## 数值与指令

Web VM 将普通数值、字符和布尔值存入单元内部；数组按引用计数和写时复制管理。可写元素引用通过原有句柄语义传递。指令使用字面量池和紧凑操作数，在 Web32 下每条指令从 24 字节缩至 16 字节。

同一第一关 Replay 的桌面 Chromium 4 倍 CPU 降速对照：

| 区间 | 原表示的每秒回调 P95 中位数 | 标量内联 |
| --- | ---: | ---: |
| 道中，帧 5,000–7,399 | 57.40 ms | 50.80 ms |
| Boss，帧 8,200–12,799 | 188.70 ms | 156.50 ms |

该桌面对照用于评估 VM 热路径。设备条件、后台负载与后续手机渲染测试分别登记。

## 跨关内存

缓存按关卡退休旧预热脚本，并保护活跃客户端。同 Replay 的匹配区间中，Wasm high-water 如下：

| 区间 | 原缓存 | 按关卡退休缓存 |
| --- | ---: | ---: |
| 三关，帧 10,000–13,999 | 396.625 MiB | 229.4375 MiB |
| 四关，帧 10,000–13,999 | 476 MiB | 275.375 MiB |
| 五关，帧 27,000–27,999 | 679.4375 MiB | 330.5 MiB |

五关区间的 Wasm high-water 下降约 51.4%，体现缓存生命周期管理的作用。统计对象为 Wasm 内存。
