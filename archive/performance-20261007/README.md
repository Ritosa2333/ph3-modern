# 手机顶点上传与显示密度 | 2026-10-07

RMX5080 主菜单的实机 A/B 将直接顶点上传与大 VBO 子更新分别测量。直接上传恢复约 60 FPS，定位了该设备上的上传策略开销。

设备为 RMX5080、Android 16、Chrome/WebView 154.0.8037.57、Mali-G720 MC7，DPR 为 3.5。测试使用相同主菜单、资源和绘制顺序，临时切换上传方法，再恢复基线。表格取切换完成后的稳定窗口，所有切换窗口收录在[原始窗口数据](results.json)中。

| 方法 | 候选呈现频率 | 恢复大 VBO 子更新后 |
| --- | ---: | ---: |
| 每次绘制直接上传，subarray 参数 | 59.94–59.98 FPS | 6.18–6.60 FPS |
| 每次绘制直接上传，WebGL2 range 参数 | 59.90–60.05 FPS | 6.13–6.32 FPS |
| 大 VBO 子更新改用 subarray 参数 | 6.27–6.51 FPS | 5.95–6.78 FPS |

前两组验证上传与存储策略的作用，第三组检查 JavaScript 参数形式。直接上传窗口的逻辑频率约为 60 Hz，呈现回调 P95 为 2.2–2.6 ms。

默认渲染路径按当前绘制的数据量直接上传。对应标准与验证构建各完成 55 个翻译单元的编译链接，44,676 个已覆盖 tick 及 11 张图像与固定基准一致，截图排除区域为 FPS 数字矩形。
